# DPE output quality gate

Apply alongside the selected domain skill. The six DPE quality specialists are adapted from Anti-Slop; licence and source revision are in docs/THIRD_PARTY_NOTICES.md.

- State the concrete outcome first. Prefer plain verbs and precise facts over generic claims, invented compound labels, filler or repeated conclusions.
- Preserve the user's voice, terminology and requested format. Do not strip personality or invent specifics to sound less generic.
- Every material factual claim needs evidence or an explicit uncertainty label. Never fabricate PASS results, runtime logs, counts, deployment status or stakeholder approval.
- Keep code comments that explain constraints or decisions; remove redundant narration only when editing is authorized. Do not change executable behavior solely to satisfy comment style.
- Apply visual/mobile/accessibility guidance only to interfaces. Existing brief, brand and repository direction govern design. Avoid adding gratuitous visual components to data engineering documents.
- Preserve useful documentation headings and order. Inject accurate information, remove contradictions and secret values, and distinguish proposals from approved/deployed behavior.
- Perform the checks proportionate to the change and report their practical limits. Do not pad a review with speculative findings or repeat all completed checks.

Routing: prose -> dpe-quality-copywriting; comments -> dpe-quality-code; interface -> dpe-quality-core + dpe-quality-ui; access/interaction -> dpe-quality-human; responsive layout -> dpe-quality-layoutmobile. For ordinary concise replies, this shared gate is sufficient.
